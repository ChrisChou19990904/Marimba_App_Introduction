1. MIDI 是什麼？

MIDI（Musical Instrument Digital Interface）是一種數位音樂通訊協議，用來讓電子樂器、電腦、控制器之間互相「說話」。 它不直接產生聲音，而是告訴音源：

  • 哪個音符要彈（Note Number）
  • 音符的強弱與敲擊深度（Velocity 力度）
  • 持續時間（Duration）
  • 音色、音量、表情控制（Control Change）

可以把 MIDI 想像成「數位樂譜」，而音源（硬體合成器或虛擬軟體插件）才是真正把聲音震動發射出來的工具。

2. MIDI 的原理與底層二進制數據

  • 事件 (Event)：例如按下 C4 音符、力度 100 或放開 C4 音符。
  • 通訊方式：傳統 MIDI 使用 5 針 DIN 接口，傳輸速率為 31,250 bps；現代則廣泛採用 USB MIDI 或低延遲藍牙 (BLE MIDI)。
  • 數據結構：MIDI 訊息通常只需 3 個 bytes（十六進制），例如： 
    0x90 0x3C 0x64  （Note On on Channel 1, C4, Velocity 100）
  • 解釋與播放：接收端（合成器或軟體音源）讀取 MIDI 指令 → 觸發振盪器振幅與包絡線 → 產生聲音。

3. MIDI vs 音頻 (WAV/MP3)

比較項目 MIDI 音頻 (WAV / MP3)
本質內容 演奏行為指令、控制訊號 實際空氣壓力震動的採樣波形
檔案大小 極小（通常數十 KB） 龐大（數十 MB 乃至更巨）
後期可調性 音色、速度、調性、力度皆可無失真即時微調 波形已固定，變速變調容易產生相位失真
運作依賴 必須仰賴音源合成器進行解算 自帶波形數據，直接驅動解碼器即可出聲

4. 對資工系和音樂系的重要性

資工系

  • 音樂軟體開發（DAW、網頁端 Web Audio 合成器）
  • 演算法與資料結構（MIDI 訊息時間佇列、優先級事件排程、時鐘同步機制）
  • 底層硬體通訊（USB、藍牙 HID 通訊與驅動介接）

音樂系

  • 編曲與演奏：無損調整指法、音符音高、擊鍵力度與演奏音色
  • 跨樂器協作：鍵盤、鼓機、類比合成器藉由主控時鐘實現同步對齊
  • 混音與製作：自動化軌道參數（Automation）、延音踏板曲線控制
核心公式：
MIDI ≈ 數位樂譜 + 控制訊號 → 音源合成器 → 物理震動聲波

5. MIDI 與應用程式的互動

以 Perfect Piano 與各類音樂引擎為例：

  • 螢幕鍵盤彈奏 → 採集 MIDI 事件（Note On/Off、Velocity 力度數值）
  • 儲存為 .mid 檔案 → 獲得純粹的演奏數據結構
  • 上傳至 MuseScore → 自動排版產生印刷級五線譜
  • 上傳至 Marble Music → 生成重力加速度滾動的彈珠音效動畫
  • 載入至 Web Audio（如 Tone.js）→ 透過程式演算法即時移調、波形切換與聲學頻譜繪製
鍵盤彈奏 → Perfect Piano 錄製 MIDI → 儲存 .mid 檔案
        ├─> MuseScore: 符號解析與自動排版為樂譜
        ├─> Marble Music: 轉為物理重力彈珠音效動畫
        └─> Web Audio / Tone.js: 網頁端即時合成、移調與 FFT 可視化

6. MuseScore vs Marble Music 優缺點比較

功能 / 平台 MuseScore Marble Music
核心定位 專業樂譜製作、排版編輯、正式出版呈現 物理動畫視覺化、彈珠節奏展示
優點
  • 自動將 MIDI 二進制指令轉為可讀五線譜
  • 可手動細調音符拍號、調性與記譜符號
  • 具備完整聲部劃分，適合學術與演奏教學
  • 小球墜落碰撞動畫直觀，極具趣味性與觀賞度
  • 完全保留原始 MIDI 演奏時長與節奏微動態
  • 操作流程極簡，上傳即可自動生成動畫
缺點
  • 真人演奏的速度微動態容易導致拍號誤判
  • 若未經嚴格量化（Quantize），樂譜記號會顯得破碎雜亂
  • 需具備基本樂理知識才能進行後續校正
  • 動畫展示長度受限（約 1 分鐘上下）
  • 視覺表現形式固定，僅限於短片觀賞
  • 無法導出印刷級五線譜或進行多軌混音

6-2. 瀑布流視覺化原理：Synthesia vs SeeMusic

除了轉換成五線譜（MuseScore）與物理彈珠（Marble Music）之外，現代網路音樂創作最常見的呈現方式為垂直瀑布流視覺化（Piano Roll Waterfall Visualization）。 這種模式將時間軸設為垂直方向，音符以色塊長條形式由上往下墜落，在觸碰到虛擬琴鍵的瞬間發聲並發光。

1. 瀑布流的底層數學映射原理

瀑布流的生成依賴於解析 MIDI 檔案中的音符事件（Note Events），並將物理時間映射至螢幕座標系（X, Y）：

  • X 軸（橫向位置）：由音符的音高數值 note.midi 決定。標準 88 鍵鋼琴的編號為 21 (A0) 到 108 (C8)，每個音符對應到畫布橫向特定的琴鍵中心座標。
  • 長條高度（Height）：取決於音符持續時間（Duration）。公式為：高度 = note.duration × 下落速度常數 (px/sec)。
  • Y 軸（縱向動態位置）：取決於「音符預計發聲時間（note.time）」與「當前播放指針時間（currentTime）」的差值。公式為：Y = 琴鍵接觸線Y座標 - (note.time - currentTime) × 下落速度。
  • 觸發碰撞與粒子特效：當 note.time ≈ currentTime 時，長條底緣接觸琴鍵判定線，系統觸發琴鍵高亮（Key Glow）、發光軍刀光束（Saber）或發射粒子（Particles）。

2. 兩大主流軟體對比：Synthesia vs SeeMusic

比較維度 Synthesia SeeMusic
核心定位 鍵盤教學、互動練習與遊戲化打分 高質感影片離線渲染、粒子視覺特效合成
運作模式 即時執行引擎：需透過螢幕錄影軟體（如 OBS）擷取畫面與音訊。 非即時離線渲染（Render）：逐幀（Frame-by-Frame）無損導出 4K MP4 影片，不掉幀、不卡頓。
視覺特效 色彩簡潔、幾何方塊分明，支援指法標記與左右手分色。 專業級渲染：支援光暈殘影、發光粒子（Particles）、鍵盤按壓波紋與實體琴鍵反光效果。
外接音源 (VST) 內建簡易 Soundfont 音源，外接高階音源需依賴虛擬 MIDI 端口（LoopMIDI）。 可直接加載高階無損 WAV 音軌，或在專案內直接掛載專業音源庫進行同步導出。
在個人工作流中的價值 適合快速檢視手動彈奏的音符指法、節奏對齊度與練習驗證。 適合將手機錄製之 MIDI 與高品質音源結合，直接輸出為可發布至社群與 YouTube 的成品影片。
💡 創作結論：
由手機雙拇指在 Perfect Piano 錄製之 .mid 檔案，具備高精度的時間差（Time Offset）與鍵位數據。透過 SeeMusic 或 Synthesia 的瀑布流映射，能將無形的二進制訊號轉換為具備強烈視覺張力的下落動畫，是「個人演奏數據化」最直觀的視覺驗證手段。

7. MIDI 與程式語言的關係

  • MIDI 本身不是程式語言，而是一種軟硬體通訊協議。
  • 工程師使用程式語言來解析二進制資料流、排程發聲、合成波形或實現聲學可視化。
程式語言 核心用途 常用函式庫 / API
JavaScript 網頁端音訊合成、即時移調、頻譜與示波器可視化 Web Audio API, Tone.js, @tonejs/midi
Python 數據科學分析、MIDI 樂譜自動轉譯、AI 音樂生成 mido, pretty_midi, music21
C / C++ 極低延遲專業音源開發、DSP 數位訊號處理、硬體控制器 RtMidi, JUCE 框架
Java 跨平台樂理軟體開發、桌上型應用 javax.sound.midi
Swift / Obj-C Apple 平台原生專業音訊與音樂 App 開發 CoreMIDI, AudioKit
C# / .NET Windows 桌面端音樂工具、Unity 遊戲音訊驅動 NAudio, Midi.Net

8. 實體電子琴與手機應用的差異

  • 實體電子琴：鍵盤尺寸符合人體工學，十指皆能靈活鋪展，可同時記錄低音八度伴奏、中音副旋律與高音主旋律，MIDI 檔案具備高密度的多聲部和弦數據。
  • 手機應用 (Perfect Piano)：限於觸控螢幕尺寸，通常僅能依靠左右大拇指敲擊。配樂不得不以主旋律為核心，但在高 BPM 節奏下需要極高的鍵位掌控力。
  • 數據等價性：雖然演奏輸入方式不同，但產生的 .mid 檔案在數據結構層級是完全標準且等價的，皆能無縫丟入專業 DAW 或視覺化引擎中播放。

9. Marble Music 自創作品上傳的條件

  • 必須具備標準的 .mid 檔案作為音符時間事件來源。
  • 創作者可親手彈奏錄製（實體電子琴或手機應用），保留原始人性化微動態。
  • 亦可使用現成或後製軟體編排之 MIDI 檔案。
1️⃣ 自己演奏 → 錄製 MIDI → 上傳 Marble Music → 自動計算碰撞判定點並生成彈珠動畫
2️⃣ 使用現成 MIDI 檔 → 上傳 Marble Music → 生成動畫
